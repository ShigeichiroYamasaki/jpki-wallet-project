# プロトタイプテストの説明と参加方法

仮想カードを読み取り、パスキーでログインし、ウォレットで署名する体験を試せます。使いやすさや説明の分かりやすさを確かめるための公開テストです。ユーザPCやスマートフォンで、サーバーの起動やターミナル操作をせずに参加できます。

**実際のマイナンバーカード、カードリーダー、JPYCの購入は不要です。** 本人確認は架空のデータによる模倣で、実際の本人確認・決済・権利移転は行いません。

## 何を試すテストか

| 体験 | 確かめたいこと | 範囲 |
| --- | --- | --- |
| 仮想カード | カードをセットして読み取る流れが理解できるか | 架空の人物による模倣。NFC・実カード・暗証番号は使わない |
| パスキー | 端末の顔認証・指紋認証などで登録・ログインできるか | 実際の公開鍵認証。公的な本人確認ではない |
| ウォレット接続・署名 | アプリ切替や署名内容を理解して操作できるか | 実際のメッセージ署名。送金・取引送信はしない |
| 模擬操作と証拠保存（任意） | 同じ操作をパスキーとウォレットで承認できるか | 合成作品の試験。実際の利用許諾は発生しない |

実カード・実PFによる本人確認、JPYC EX連携、JPYCの発行・償還、実作品の権利審査は、このテストに含まれません。証拠ファイルは独自の試験形式で、W3C VCとの相互運用や法的な証明力を確認したものではありません。本認証基盤の法的整合性は専門家による精査が必要です。

## 参加前に用意するもの

| 利用環境 | 準備 |
| --- | --- |
| iPhone | Safari、パスキーを作成できる端末設定、MetaMaskアプリと利用可能なアカウント |
| ユーザPC | パスキーに対応した通常ブラウザと認証器、同じブラウザに導入したウォレット拡張 |

iPhoneのパスキー操作はSafariで、ウォレット接続・署名はMetaMaskアプリで行います。アプリ内ブラウザではパスキー操作ができない場合があるため、Safariを起点にしてください。Android等の組み合わせは、この案内では動作確認済みとは扱いません。

テスト専用のウォレットアカウントを推奨します。署名のみの試験なので、JPYCやガス代用の残高を用意する必要はありません。ウォレットを用意しない場合も、仮想カードとパスキーまで試せます。

## 操作手順

### 1. 仮想カードを読み取る

「この仮想カードをセット」を押し、続いて「仮想カードを読み取る」を押します。画面の「サンプル利用者 A」は架空の共通データです。実際のカードを端末にかざす必要はありません。

### 2. パスキーを登録してログインする

初回は「初めて利用する」を押し、端末の案内に従ってパスキーを作成します。その後、**「パスキーでログイン」を押してください。登録だけではログインは完了しません。**

2回目以降は、このサイトに登録したパスキーでログインします。以前のlocalhostの試験用パスキーは利用できないため、公開サイト用に登録してください。

ログイン後、仮想カードの結果が自動で確認されます。失敗した場合は「仮想カードの確認を再試行」を押します。

### 3. ウォレットに接続し、署名する

iPhoneでは次の順序で操作します。

1. Safariで「ウォレットに接続」を押す。
2. MetaMaskアプリで接続先を確認して承認する。
3. **Safariの元のタブへ戻る。**
4. Safariで「ウォレットで署名」を押す。
5. MetaMaskでメッセージの内容を確認して署名する。
6. Safariへ戻り、署名の検証結果を確認する。

PCではウォレット拡張の案内に従います。接続の承認とメッセージの署名は別の操作です。接続先はこのプロジェクトのGitHub Pagesであることを確認してください。

ページを再読み込みせず、元のタブへ戻ってください。再読み込みされた場合は、仮想カードの読み取りとパスキーでのログインをやり直します。

### 4. 模擬操作の署名と証拠保存を試す（任意）

「内容を確認して署名」から、合成作品に対する許諾試験の内容を確認し、パスキーとウォレットの両方で承認します。「証拠ファイルを保存」から結果を保存できます。実際の作品に対する権利変更や利用許諾は発生しません。

ウォレット署名の検証まで完了すれば基本のテストは終了です。任意の操作や証拠保存まで進む必要はありません。

## ボタンが押せない・途中で止まったとき

| 状況 | 対処 |
| --- | --- |
| 「初めて利用する」が押せない | 仮想カードのセットと読み取りを先に完了する。iPhoneではSafariで開く |
| 「ウォレットに接続」が押せない | パスキー登録後にログインする。仮想カードの確認が失敗した場合は再試行する |
| MetaMaskから戻っても終わらない | 接続承認の後、Safariで「ウォレットで署名」を押す。署名後もSafariへ戻る |
| 時間切れ・認証が切れた | パスキーでログインし直し、接続・署名をやり直す |
| アプリ切替後にページが再読み込みされた | 仮想カードの読み取りとパスキーログインをやり直す。登録済みなら新規登録は不要 |
| APIへ接続できない | 少し待って再試行する。改善しなければ、表示されたエラーと発生した手順を報告する |

この試験版にはアカウント復旧機能がありません。端末やパスキーを失った場合の復旧は保証できません。

## テストデータの取扱い

パスキーの公開鍵・登録情報、ウォレットアドレス、署名の検証に必要な情報、模倣結果や操作の証拠などを試験システムで扱います。実氏名・個人番号・カード画像・本物の暗証番号は入力しません。秘密鍵やウォレットの復元フレーズを本サイトへ入力する手順もありません。

MetaMaskへの接続には同社の中継サービスを利用します。メッセージ署名の対象はウォレットへ渡ります。保存した証拠ファイルにはウォレットアドレスなどが含まれ得るため、公開の報告へそのまま添付しないでください。

試験データの保持・削除の実装状況は[技術資料](/cloud-prototype)と[実装README](https://github.com/ShigeichiroYamasaki/jpki-wallet-project/tree/main/services/cloud-prototype)に記載しています。画面を閉じることや端末上のパスキーを削除することは、サーバー上の試験データの削除を意味しません。大人数への拡大前に、保存期間・削除受付・実験終了時の取扱いを確定して案内します。

## 感想・不具合を知らせる

テストを案内した担当者へ伝えるか、[GitHub Issues](https://github.com/ShigeichiroYamasaki/jpki-wallet-project/issues/new)へ報告してください。Issuesへの投稿にはGitHubへのログインが必要です。

- 使用端末とブラウザ、分かる範囲のOSバージョン。
- 完了した手順、止まった手順、表示されたエラー文。
- 分かりにくかった説明、アプリ切替で迷った点。
- おおよその所要時間と、改善してほしい点。

公開の報告には個人情報、復元フレーズ、秘密鍵、証拠ファイルを記載・添付しないでください。画面画像を送る場合は、アドレスなど共有したくない情報を隠してください。

## 検証計画とこれまでの記録

100人は段階的な参加規模の目標であり、収容実績や同時接続数の保証ではありません。仮想カードでは実人物の一意性を確認できないため、実際の重複参加抑止を検証したとは扱いません。

| 段階 | 検証内容・進める条件 |
| --- | --- |
| 少人数での操作確認 | 登録完了率、所要時間、離脱した手順、端末・ウォレットの組み合わせを確認 |
| 障害・運用の確認 | 期限切れ・再読み込み・状態の誤表示、問い合わせ対応、削除手順を確認 |
| 10→30→100人への拡大 | サーバー負荷・費用・運用体制・情報管理を確認して段階的に判断 |
| 将来の追加案 | JPYC EXの模擬手続きとテスト用トークンによる支払い。現行テストには未実装 |

iPhoneでの仮想カード・パスキー・MetaMaskの一連の操作について、利用者から成功の報告を得ています。すべての端末・OSでの動作保証や、多人数での検証完了を意味しません。

2026年9月7日の初期検証では、Docker基盤とPF・証明書確認の7シナリオを模倣し、既存VMへ試験配置しました。応答遅延によりその配置は停止した記録があります。その後の参加者向け構成はGitHub PagesとCloud Runです。旧VMの停止記録を、現在の公開テストが停止中という意味には扱いません。

当時の実装・工程表は[ホワイトペーパー旧版](https://github.com/ShigeichiroYamasaki/jpki-wallet-project/blob/7524352828177acbec65983ada78142b3658e25e/docs/whitepaper.md)で確認できます。実カードを扱ったローカル試験は過去の検証記録として保持し、現在の参加手順からは分離しています。
